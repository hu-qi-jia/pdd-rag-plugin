# 检索管线不拆 npm 包,目录分层即边界

长期项曾提出"检索管线 / pdd-dom 包化"。评估后决定**不做**:第二十九轮目录重构已把包化想解决的边界问题落地——`src/shared/`(跨上下文基础设施)、`src/pdd/`(平台领域纯逻辑)、`src/types/`(纯类型)各自成层,靠 tsc 相对导入与分层约定约束;边界本身已清晰可导航。

npm workspace 能额外提供的只有两件事:机器强制的依赖方向(package.json 依赖声明)与独立版本化/发版。本扩展两者皆不需要——没有第二个消费方,不存在独立发版节奏;单人项目里 review 即约定执行。而代价是实打实的:Plasmo 单体构建需为拆包引入路径别名/构建配置,四个上下文(background / offscreen / contents / popup)的产物组合复杂度上升,单人维护反而更脆。

触发重估的条件(出现其一再议):检索管线需被第二个项目复用;或协作人数多到约定不再可靠、需要机器强制边界。
