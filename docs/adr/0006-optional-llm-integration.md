# 有条件豁免"数据不出本机":用户自配 API 的知识库整合(默认关)

## 背景

`docs/工作状态-2026-09-08.md` 记过一次决断:用户问是否要接生成模型,结论是**暂不接** —— 云端 LLM 违反"数据不出本机"红线,本地生成模型在扩展里又太重。

那条决断今天仍然成立,但它回答的是"要不要**默认**接生成模型"。实际使用中暴露出另一件事:知识库检索出来的原文**不等于最终回答** ——
FAQ 类文档的块天然带着问题行、编号、相邻条目的残留;长文档的块更是多个话题的混合体。客服要的是"能直接发出去的一句话",不是"要自己读一遍再改写的原文"。
纯检索能解决"找得到",解决不了"能直接用"。

与此同时,红线本身没有被推翻:用户仍然明确要求**历史回答与标准回答永不外发**、**发送始终由人工点击**。

## 决策

在不推翻"数据不出本机"的前提下,开一条**窄的、需用户逐次触发的**豁免通道:

只有**同时满足**下列三条,才有数据离开本机:

1. 用户在设置里**显式填写**了第三方 LLM 的接口地址、API Key 与模型名(即 `isLlmConfigured` 为真);
2. 用户**显式打开**「AI 整合」开关(`aiIntegrateEnabled`,**默认 false**);
3. 用户**主动点击**推荐面板里的「根据知识库内容整合并回复」行。

外发内容**仅限**:本轮面板展示的**知识库候选文本** + **当前买家问题**。

> 知情口径(2026-09-17 第四十八轮补):条件 ③ 的点击是**知情点击**——
> 该行在点击之前就把边界写在行内(「点击后把命中的 N 条知识库内容发给你配置的接口 /
> 只发送这条买家问题,历史回复与标准回答不出本机」),不必去设置页翻说明。
> 这段文案与上面的"外发内容仅限"必须同源同义,改动任一处都要同时核对另一处。

## 边界(硬约束)

- **历史回答与标准回答永不外发**。它们只走本地检索,不进 `collectMaterials` 的入参;
  该函数的唯一调用点是 `handleAiIntegrate`,入参是面板里 `kind === 'knowledge'` 的候选 id。
- **开关默认关、配置默认空**,不开启时扩展运行期零远程请求(与 ADR-0005 的合规口径一致)。
- **发送永远由人完成**。整合结果只 `fillInput` 进输入框,扩展从不代发。
- **API Key 只进 `chrome.storage.local`**,不进 `chrome.storage.sync`,不随导出外发。
- **主机权限按 origin 现申请**(`optional_host_permissions`),安装时不索取任何新权限;
  用户看到的是 Chrome 原生的"允许访问 xxx"提示,授权范围就是他亲手填的那个域名。
- **不做深度思考**。请求体不含任何 reasoning/thinking 参数,交互定位是"整合"不是"推理"。
- **不再外发任何其他东西**:无遥测、无日志上报、无模型名之外的元数据。

## 代价与取舍

- 红线从"绝对不出本机"变成"用户主动点一下才条件性出本机"。这是本 ADR 唯一的实质让步,
  用三道显式动作(填配置 / 开开关 / 点那行)换"客服能直接把话发出去"。
- 用户可能配错地址或密钥导致整合失败 —— 用「测试连接」把失败提前到设置页,
  且错误文案带上 HTTP 码,让用户知道该改哪一项。
- 扩展开始依赖外部服务可用性:超时上限 30s(默认 8s),超时/网络失败均只影响整合行,
  不影响下方的检索候选 —— 后者是纯本地的,永远可用。

## 触发重估的条件(出现其一再议)

- 若被商店以"数据传输"为由拒绝上架,则改为**只在开发者模式/离线 zip 版本**提供本功能;
- 若用户普遍把历史回答也误当成会外发的内容(信任受损),则把开关改为每次点击都二次确认;
- 若本地小模型在普通办公机上能跑到可接受的首字延迟,则回到"完全本地"的原红线,
  本 ADR 作废。
