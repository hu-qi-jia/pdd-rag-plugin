## 〇-GG、2026-10-17 第五十九轮:问题类型重制(八记录级 + 尺码查询级专用 + 两条阈值常量)(单测 965/965(73 文件),tsc 0 错,build 过)

上承第五十六~五十八轮的问题自动分类(地基 → 面板与设置页 → 检索路由与尺码路由)。
那三轮把分类**存了下来、也让人看得见、还改变了检索去向**,但**类型集合本身**一直沿用第五十六轮定的六个预置类型。
本份只改**类型集合与它的作用域** —— 不改分类调用协议、不改检索排序(RRF / 时间衰减 / `FILTER_MARGIN`)、
不改外发边界(ADR-0007 仍成立)。

设计见 `docs/specs/2026-10-16-category-taxonomy-redesign-design.md`(八条 criteria、迁移八步、验收清单);
计划见 `docs/plans/2026-10-16-category-taxonomy-redesign.md`(7 个 Task,起点 `1fc7386`)。
这两份由 controller 在实现开始前提交。

> **★本轮的承重事实**:同一套类型集合过去**同时在干两件性质不同的事** —— 给记录归档、给查询路由;
> 于是「尺码推荐」这种"答案不可复用、只该出现在意图识别里"的类型,在「历史问答」「标准回答」两个页面上
> **也成了一个桶**。本份把**记录级**选项集收成 `filterable && route === 'retrieve'`、**查询级**保持 `filterable`,
> 两个作用域从此分得开,并由测试钉住不再漂回同一个集合。

### 一、类型集:六个预置 → 八个记录级 + 「其他」

- **复用 id、只改名与判据(五条)**:`preset:attribute` 商品属性→**商品信息**、`preset:stock` 库存发货→**库存与规格**、
  `preset:order` 订单物流→**发货与物流**、`preset:aftersale` 售后退换→**退换货**、`preset:price` **价格优惠**
  (名不变,criteria 收紧)。id 未变 ⇒ 存量标签原地保留有效。
- **新增三条**:`preset:payment` **支付与发票**、`preset:quality` **质量与维修**、`preset:other` **其他**(初始为空)。
- **`criteria`(判定说明)逐字抄自 spec §4.1**,原样发给分类模型;每条都写了"不含什么"来划边 ——
  不划边两类就完全重叠,argmax 退化成掷硬币。spec 表格里的 `**` 是文档强调、不属于 criteria 文本,
  落进代码前已去掉(实现中途的 fix 轮)。
- **「其他」是正式选项**:`kind:'preset'`、`filterable:true`,与指令里的出口句
  (「…如果都不属于,选「其他」」)以及它 criteria 里的反向约束(「仅仅因为你没把握而选它是错的」)配套 ——
  一个开出口、一个防泛滥,缺一则失衡。
- **为什么要重制**:真实导出(68 条问答 / 7 个类型)里「商品属性」吞了 39/68(57%)、「发票」8 条 100% 挤进「售后退换」、
  **一条都没落「未分类」** —— 类型集里既没有发票桶、也没有出口桶,模型只能硬塞;同时置信度 ≥0.9 的有 45 条,
  说明"落在错桶里的时候一样自信",**调阈值治不了缺桶**。

### 二、★记录级与查询级分开(本次的核心结构改动)

- `classifiableCategories(cats, scope)`:`record` → `filterable && route === 'retrieve'`;`query` → `filterable`
  (**与加作用域之前行为相同**)。三个调用点全部带 scope:`classifyRecord`(捕获打标)、`runBackfill`(补存量)、
  `backfillState`(起始门禁)走 `record`,`classifyForQuery`(每次检索)走 `query`。
  `scope` **无默认值** —— 有默认值会让"忘了传"静默退回旧行为,正是要修的病根。
- **用现成的 `route` 判,不新增字段**:`route='size'` 的定义就是"答案取决于买家个体参数、历史回复不可复用"——
  这种类型下永远不该有存档记录,两个概念天然重合,不需要 `scope`/`recordLevel` 第二个开关。
- **两个归档页面不再显示「尺码推荐」**:`PanelCategory` DTO 加 `route` 字段,UI 侧用**一处**共享谓词
  `recordLevelCategories`(`popup/logic.ts`)过滤「历史问答」「标准回答」的类型导航 / 筛选 / 「移到其他类型」选择器。
  谓词是**黑名单**(`route !== 'size'`)而非白名单,这是有意的:DTO 或测试桩缺字段时白名单会**静默清空整片导航**。
- **尺码路由**(`route='size'`、尺码表文档标记、`sizeRowAvailable`、面板尺码生成行)**全部保持可用** ——
  「尺码推荐」没退休、没删。一开始把它判成"死代码"是错的。

### 三、两条阈值常量(耦合在一起的一处坑)

- `DEFAULT_SETTINGS.classifyProbThreshold` 0.2 → **0.5**;`LOW_CONFIDENCE_LINE` 0.5 → **0.65**。
- **两条是耦合的,这是本轮最不显然的一处**:记录被打标要求 `p ≥ 阈值`(`pickRecordCategory`),
  而 `isLowConfidenceCategory` 判的是 `p < 复核线`。**若复核线 ≤ 阈值,两个条件永不同时成立,
  「低置信」标记与它的浮层整个静默失效**(不是少标几条,是整个功能不出现)。所以复核线必须**严格大于**默认阈值 ——
  抬到 0.65 之后,三个量(打标 / 标记低置信 / 不许收窄检索的守卫)各归其位。`route.ts` 的注释本就要求
  「标记线」与「不许收窄线」共用同一条,故抬的是一条共用线,两侧同时恢复含义。
- 这条不变量由 `tests/unit/shared/lowConfidence.test.ts` 钉住(`LOW_CONFIDENCE_LINE > 默认阈值`)——
  阈值降到 0.5 时它会当场变红。

### 四、Dexie `version(9)` 迁移(存量库对齐)

- `ensurePresetCategories` 是**只增不改**的,所以常量改名后,跑过旧版的库里那些行**仍持旧名** ——
  迁移的第一件事就是五条改名、三条新增、position 重排(八个记录级 0..7、`preset:size` 排 8、
  非预置非未分类的行推到 ≥9 保序)。
- **最容易写错的一处是时间戳**:补分类的重跑判据是 `(rec.categoryAt ?? 0) < catUpdated`,而 v8 迁移
  **刻意**让两者取等(让标答不重跑);本次要的正是重跑,所以被改动的类型 `updatedAt` 必须**严格大于**存量
  `categoryAt` —— 取等会让一条都不重判:界面列着新类型、归类仍是旧标准,且**无报错**。
- **名称唯一性守卫**:分类模型以**类型名**为键构造选项映射,同名会让后一行静默顶掉前一行;
  迁移路径不经过 `createCategory` 的查重(v8 从用户文件夹名造 `legacy:*` 时不查重、criteria 为空串),
  故**新增之前**先把占用预置名的非预置行改名让开(追加「(旧)」)。守卫对**全部九个**预置名生效,不只新增那三条 ——
  改名同样会撞(用户有个叫「退换货」的旧文件夹时,`preset:aftersale` 改名就撞上)。
- **不做任何删除**:全程无 `delete`,`preset:size` 保留;`qaRecords` / `goldens` **只读不写**。

### 五、spec §十 留给实现者的判断,实际选了什么

- **`updatedAt` 偏移的取法** → **`stamp = max(now, 存量最大 categoryAt + 1)`**(不是固定偏移);
  一次取最大、值固定;取 max 用 `for` 循环而非 `Math.max(...spread)`,几万条记录不炸栈。
- **`PRESET_CATEGORIES` 一个数组还是两个导出** → **一个九条数组**(八个记录级 + 末尾 `preset:size`),
  `preset:size` 上方加了"查询级专用"注释。
- **记录级与查询级是否共用一句 `INSTRUCTIONS`** → **共用一句**(spec §6.2 的倾向):指令说的是"从给定选项里选",
  选项表本身由 `criteria` 决定,不由指令决定,故不必按 scope 拆成两句。
- **共享的作用域谓词叫什么、放哪** → 后台侧是 `classifiableCategories(cats, scope)`(`background/classify.ts`,仅此一处);
  UI 侧是 `recordLevelCategories`(`popup/logic.ts`,仅此一处)。
- **八条 criteria 的措辞** → **逐字抄 spec §4.1**(只去文档强调记号 `**`),未再打磨。
