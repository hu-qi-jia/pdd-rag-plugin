### 一、保留期档位卡死(修复)

- **现象**:保留期已是 90 天 → 点「自定义」→ 点回「90天」,选中态仍停在「自定义」,
  下方自定义输入行也不收起。
- **根因**:`onChange` 的预设分支只 `persist`、不改 `retentionMode`;而同步 effect 的依赖是
  `draft.retentionDays`,90→90 没有变化,effect 不重跑,于是状态停在 custom。
  只有"切到一个不同的预设值"才会被 effect 救回来。
- **修复**:点击时先 `setRetentionMode(choice)`,再落库。回归断言在
  `tests/unit/ui/settingsPreferences.test.tsx`(自定义 → 同值预设)。

## 九、同日新增:图片回复进记忆(2026-10-23)

> 同日早些时候做过「会话上下文条」(把右侧商品面板投影成聊天区左上的一行旁注),
> 用户评价"没意义",**已整体删除** —— `src/pdd/right-panel.ts`、`right-panel.test.ts`、
> `.pddcs-ctx` 样式与设计文档 §6.4 都已回退,树里不再有这套东西。

图片消息(客服/买家)现在作为一等消息进入捕获与记忆。三步走的前两步已落地:

**① 捕获 + 存储 + 展示**

- 形态(真机校准):`<div class="msg-content image-msg">` 里一张
  `img.img-msg-thumb`,`src=https://chat-img.pddugc.com/chat-pic-mall-cs-v1/<日期>/<uuid>.jpeg?imageMogr2/thumbnail/800x800gt;`。
  实测是**公共 CDN 直链**:无签名、无过期参数,`Access-Control-Allow-Origin: *`,
  `Cache-Control: max-age=31536000`;剥掉查询串即原图,原图 225KB、200px 缩略图 19KB。
- 存储只存 URL(`ImageAttachment{type,url}`),不下载二进制;缩略图在展示侧拼
  `?imageMogr2/thumbnail/WxH`(`shared/images.ts#thumbUrl`,只对拼多多图片域加参数)。
- 捕获:dom-parser 识别 `.image-msg img.img-msg-thumb`,纯图片消息正文记为 `[图片]`
  (`shared/constants.ts#IMAGE_PLACEHOLDER`);商品卡/表情仍跳过。
- 分段:客服图片算回复(关闭问题段、附件挂到回复),买家图片并入问题段(占位符只记一次)。
- 幂等:`contentHash` 与候选折叠键统一走 `hashReplyContent(text, attachments)` ——
  否则同问题下不同图片会因正文同为「[图片]」被折叠成一条。纯文本口径不变,存量哈希不受影响。

**② 标准回答带图**

- 从历史回复"设为标准回答"时自动复制附件(回复被 TTL 清掉后,标答里的图还在);
- 标准回答编辑器可增删图片(粘贴 URL),只改图不触发重嵌;
- 候选弹窗与记忆列表显示 44–48px 缩略图;纯图片候选**一律不参与填充**:
  直填判定、自动回复、键盘 Enter、弹窗转发填充四条路径都加了同一道守卫
  (`ui-logic.ts#isImageOnlySuggestion`),任何一条漏掉都会把「[图片]」四个字写进输入框。
- **图片改成"选中即发送"**(2026-10-24 按用户要求):点选/回车图片候选 → 取 800px 缩略版 →
  `DataTransfer` 设进平台隐藏的 `input[type=file][accept*=image]` → dispatch change →
  平台弹自己的「是否发送图片」→ 扩展在 3 秒窗口内找到并点「发送」。
  这是全项目**唯一替人按发送键**的地方(设计文档「姿态」已同步改写);
  没弹框/没点到就如实提示"已上传,请手动确认",并退回页内预览。
  缩略图点击仍是页内大图预览,不跳标签页。
- **客服连续消息合并成一条回复**(2026-10-24,用户要求):分段器新增"未结回复段",
  与买家问题段同一条合并规则 —— 客服的"一句话 + 一张图"、连补两句都落成**一条** replies;
  买家再次开口 / idle / leave 时 flush。快照结构随之改为 `{questions, replies}`
  (旧快照兼容读取);客服消息**不再在 ingest 入口按 msgId 丢弃**(否则重放会少一句),
  幂等交给 flush 时的 contentHash 与段首 msgId。
  纯图片回复正文存空串,买家纯图片问题仍补 `[图片]` 占位符;面板在"有附件且正文为空/占位符"时
  只显示图、不显示那四个字;带图候选不进"直填/自动选择首条",一律退回面板让用户点一次。
- **「选中即发送」当日实现又当日砍掉**(2026-10-24,用户决定)。过程与结论留档:
  - 先后试过:合成 click / 派发 Enter / 按 `.send-btn` 精确点击 / 等待 Vue tick —— 全部无效;
  - 读源码后确认原因(见下条),改用主世界调组件方法,真机确实能发(纯文字与图文合并都验过);
  - 但该方法名是混淆产物、随平台改版而变,用户判断风险大于价值 → **整体移除**:
    `PddSettings.sendOnSelect`、设置页开关、`ui-logic#planSuggestionUse`、
    `background/mainWorldSend.ts` 与 `PDD_SEND_TEXT` 消息全部删掉;
  - 现在的口径:选中候选**只填充/上传**;纯图片或图文候选会把图**上传进输入框**
    (触发平台自己的「是否发送图片」),发送一律由人工确认 —— 扩展不代点确认、不代按发送键。
  - 合并边界:以**问题**为界 —— 买家一开口就丢弃回复段,新问题后的客服消息必然另起一条;
    新增单测钉住这一点(同一问题内合并、跨问题不合并)。
  - 保留的改动:设置页「自动回复」改名为「自动选择首条」。
- **发送的真实拦路虎(2026-10-24 下午,读源码 + 真机验证)**:平台「发送」按钮的处理器开头有
  `t && void 0 !== t.isTrusted && !t.isTrusted` 守卫 —— **合成 click / Enter 一律被静默丢弃**
  (实测 capture 能收到 click,但 `sendResolvedMsg` 调用次数为 0)。改法:后台用
  `chrome.scripting.executeScript({world:'MAIN'})` 找到 `.reply-box` 祖先上的 `middlePanel`
  组件,按"方法体含 isTrusted"识别出混淆的发送方法(`aqdhv1fwak9sendBtn`),以
  `{isTrusted:true}` 假事件调用它 —— 平台内部校验(内容/手机端已回复/致歉语)照常执行。
  真机验证:纯文字候选一次点击即发出;文字+图片合并候选一次点击后,文字与图片先后到达。
- **"历史回复不记录了"的根因与修复(2026-10-24)**:合并回复最初做成"等买家开口/空闲才落盘",
  加上页面刷新后**整表重放**(买家消息在入口按 msgId 被拦下、客服消息没有),几十条旧客服消息
  重新进入分段器 → 被合并成一条并挂到最早的问答上,新回复看起来"没记录"或记到了旧问题下。
  三处一起改:
  1. 回复段**每条消息即时写库**(首条新建、后续带 replyId 更新同一条);
  2. 内容脚本的"已处理行 id"存进 sessionStorage(同标签页刷新后重放真正变成 no-op);
  3. 未结回复段不再从快照恢复(SW 重启后宁可让下一条消息另起一条,也不复活旧段)。
  真机验证:发送"记录测试Z11"后,记忆页回复数 50→51,该条挂在最新的"看看小猫"问答下。
- 导出/导入信封原样携带 `attachments`(旧包没有该字段 → 按无图处理,`EXPORT_VERSION` 不变)。

**③ 未做**:本地缓存 blob(捕获时下载进 IndexedDB、导出转 base64)。
CDN 目前允许 CORS,技术上可行;等观察到链接失效再开这个开关。

### 二、全局连续圆角(corner smoothing 60%)

用户要求「全局圆角优化,corner smoothing 60%,要 iOS 圆角的效果」。

- **口径**:新增 `design.ts#cornerSmoothing = 0.6` 与派生 `cornerShapeK = 1 + s × 5/3`(0 → 1 正圆,
  0.6 → 2),`cornerShape = superellipse(2)`。Chrome 的 `k=1` 就是 `round`(`k=2` 是它自己的
  `squircle` 关键字),所以 60% 正好落在 `squircle`。
- **实现**:CSS `corner-shape: superellipse(...)`(Chrome 139+,真机 156 / Playwright Chromium 145
  都支持;**不支持的浏览器忽略声明,自动退回普通圆角**)。没有用 `clip-path` 生成 path ——
  那套会把 box-shadow 一起切掉,而卡片与浮层都靠阴影。
- popup 用**一条 `*` 通配规则**(圆角散在三十多条规则与内联样式里,枚举一定漏);
  聊天页覆盖层限定成 `#pddcs-overlay, #pddcs-overlay *` —— 那份样式注入的是拼多多页面。
- **胶囊与正圆回到 `round`**:开关轨、拨柄、滑杆轨道/拇指、分类 pill、18px 圆钮、
  图片预览关闭钮。它们的语义是"全圆端",被抹成超椭圆反而像削角。
- 验证(headless,非截图判断):
  - 实测 `getComputedStyle` —— 卡片 15px / 按钮 13px / 设置页档位轨道 = `squircle`;
    开关轨 / 拨柄 / 分类 pill = `round`;
  - 命中域探针(80×80、圆角 20 的左上角 20×20 逐像素采样):正圆外侧 222 点、超椭圆 44 点,
    形状确实被引擎画成了超椭圆,不只是解析了个属性;
  - 像素级比对确认 **box-shadow 跟随新形状**((20,20)~(28,28) 对角线上 4/9 采样点不同:
    超椭圆更早进入填充区),不存在"影子还是圆角、块已经变方"的错位;
  - 4× 放大的卡片角与按钮角目视连续、没有过方。
